# Architecture

> Этот документ описывает общую архитектуру NeuroCore и взаимодействие всех её компонентов.

---

# Общая идея

NeuroCore представляет собой модульную когнитивную архитектуру.

Каждый модуль отвечает только за одну задачу.

Модули взаимодействуют исключительно через определённые интерфейсы.

Ни один модуль не должен знать внутреннее устройство другого.

Архитектура построена таким образом, чтобы любой компонент можно было заменить без переписывания всей системы.

# Основные компоненты

Архитектура состоит из девяти независимых подсистем.

```
Perception
Knowledge Compiler
Memory
Working Memory
Reasoning
Planner
Execution
Critic
Learning
```

Каждая имеет единственную ответственность.

---

# Perception

## Назначение

Получение информации из внешнего мира.

Сам Perception ничего не понимает.

Он только преобразует внешний формат во внутренний.

Например

```
PDF

↓

Text
```

или

```
Speech

↓

Text
```

или

```
Image

↓

OCR

↓

Text
```

или

```
API

↓

JSON
```

---

# Knowledge Compiler

Самый важный модуль проекта.

Он превращает необработанный текст в знания.

```
Text

↓

Tokens

↓

Syntax

↓

Semantic Frames

↓

Knowledge Objects
```

Компилятор знаний полностью отделён от памяти.

Он ничего не сохраняет самостоятельно.

---

# Memory

Memory является центральной частью системы.

Все знания существуют только внутри памяти.

Никакой другой модуль не хранит знания постоянно.

Memory отвечает за

- хранение;
- индексацию;
- поиск;
- связи;
- версии;
- происхождение знаний.

---

# Working Memory

Рабочая память содержит только активную часть знаний.

Она используется во время рассуждений.

Особенности

- ограниченный размер;
- распространение активации;
- затухание;
- приоритет внимания.

Working Memory никогда не является долговременной.

---

# Reasoning

Reasoning отвечает за применение способов мышления.

Он не знает предметную область.

Он знает только алгоритмы рассуждений.

Например

- дедукция;
- аналогия;
- абдукция;
- поиск противоречий;
- объединение знаний;
- вывод новых фактов.

---

# Planner

Planner отвечает за достижение целей.

Он получает

```
Goal
```

и превращает его в

```
Execution Plan
```

Planner не выполняет действия.

Он только строит план.

---

# Execution

Исполнитель выполняет план.

Он взаимодействует

- с Python;
- инструментами;
- файловой системой;
- браузером;
- интернетом;
- терминалом.

Execution ничего не анализирует.

Он только выполняет.

---

# Critic

Critic анализирует результат.

Например

```
План

↓

Выполнение

↓

Ошибка

↓

Причина ошибки

↓

Урок
```

Урок сохраняется обратно в память.

---

# Learning

Learning отвечает за изменение знаний.

Он может

- увеличить уверенность;
- уменьшить уверенность;
- объединить знания;
- разделить знания;
- создать новые связи;
- удалить ошибочные знания.

---

# Архитектурные правила

## Правило №1

Каждый модуль выполняет только одну задачу.

---

## Правило №2

Модули не знают внутреннее устройство друг друга.

---

## Правило №3

Все знания проходят через Knowledge Compiler.

---

## Правило №4

Никакой модуль не имеет права изменять память напрямую.

Все изменения проходят через Memory API.

---

## Правило №5

Reasoning не знает о PDF, HTML, JSON или интернете.

Он работает только со знаниями.

---

## Правило №6

Execution не умеет думать.

Execution только выполняет действия.

---

## Правило №7

Critic никогда не принимает решения.

Он только оценивает результат.

---

## Правило №8

Learning никогда не создаёт знания самостоятельно.

Он только изменяет существующие знания или сохраняет новые результаты работы других модулей.

---

# Почему такая архитектура

Такое разделение позволяет

- заменить LLM без изменения ядра;
- заменить LMDB без изменения логики;
- заменить граф другим способом хранения;
- добавить новый источник знаний;
- добавить новый способ рассуждения;
- добавить новую память.

Все остальные части системы продолжат работать без изменений.

---

# Итог

NeuroCore представляет собой не монолитную программу, а совокупность независимых когнитивных модулей, связанных единым жизненным циклом знаний.

Главным объектом архитектуры является не модель ИИ и не граф данных, а **Knowledge Object**, проходящий путь от получения информации до долговременного хранения, использования, проверки и последующего обучения.
