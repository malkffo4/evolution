# Principles

Version: 1.0

---

# Назначение

Данный документ описывает фундаментальные принципы проекта.

Это не описание реализации.

Это правила, которые должны соблюдаться независимо от языка программирования, используемой модели, структуры базы данных или внутренней реализации компонентов.

Любое архитектурное решение должно соответствовать данным принципам.

Если новая идея нарушает один или несколько принципов, необходимо изменить реализацию, а не сами принципы.

---

# Principle 1

## Память важнее модели

Главным компонентом системы является память.

Не языковая модель.

Не алгоритмы.

Не поиск.

Не планировщик.

Именно память содержит знания, накопленный опыт и способы решения задач.

Любая модель искусственного интеллекта рассматривается как сменяемый инструмент.

Память должна переживать замену моделей.

---

# Principle 2

## Любая информация становится знаниями

Источник информации не имеет значения.

Это может быть:

- книга;
- статья;
- документация;
- PDF;
- изображение;
- звук;
- видео;
- программа;
- интернет;
- собственный опыт.

После восприятия информация должна быть преобразована в единое внутреннее представление знаний.

После этого система больше не работает с исходным источником.

Она работает исключительно со знаниями.

---

# Principle 3

## Внутреннее представление едино

Не существует отдельных представлений для:

- книги;
- статьи;
- RFC;
- Википедии;
- исходного кода;
- разговора.

После обработки все они становятся одинаковыми объектами памяти.

Все подсистемы работают только с внутренним представлением знаний.

---

# Principle 4

## Код не содержит предметных знаний

Исходный код не должен содержать знания о мире.

Код содержит только универсальные механизмы:

- память;
- поиск;
- индексацию;
- распространение активации;
- виртуальную машину;
- выполнение;
- планирование;
- оценку.

Все знания находятся исключительно в памяти.

---

# Principle 5

## Любое знание является объектом памяти

Система не разделяет знания по происхождению.

Любое знание является объектом памяти.

Например:

- понятие;
- определение;
- факт;
- правило;
- алгоритм;
- процедура;
- гипотеза;
- наблюдение;
- событие;
- вопрос;
- цель.

Все они имеют одинаковую архитектурную основу.

---

# Principle 6

## Любое мышление является работой над знаниями

Мышление не является отдельной сущностью.

Любой процесс мышления представляет собой преобразование существующих знаний.

Например:

дедукция;

аналогия;

абдукция;

планирование;

поиск причин;

построение гипотез.

Все они работают исключительно с объектами памяти.

---

# Principle 7

## Алгоритмы являются знаниями

Способ мышления тоже является знанием.

Алгоритм не должен быть жёстко встроен в программу.

Он должен существовать как объект памяти.

Это позволяет:

изменять алгоритмы;

создавать новые алгоритмы;

комбинировать существующие алгоритмы;

оценивать успешность алгоритмов;

обучаться новым стратегиям решения задач.

---

# Principle 8

## Любое решение должно быть объяснимым

Каждый вывод должен иметь происхождение.

Система должна иметь возможность показать:

какие знания использовались;

какие правила были применены;

какие гипотезы появились;

почему был выбран именно этот вариант.

Отсутствие объяснения считается архитектурным недостатком.

---

# Principle 9

## Любое знание имеет происхождение

Для каждого знания должны храниться:

источник;

время появления;

степень доверия;

способ получения;

история изменений.

Невозможно использовать знания без информации об их происхождении.

---

# Principle 10

## Любое знание может быть пересмотрено

Система никогда не считает знания абсолютно истинными.

Каждое знание может:

быть уточнено;

быть дополнено;

быть объединено;

быть опровергнуто;

быть удалено.

Интеллект невозможен без изменения собственных убеждений.

---

# Principle 11

## Система должна уметь забывать

Память не является архивом.

Неиспользуемые знания могут:

ослабляться;

архивироваться;

объединяться;

удаляться.

Рост памяти не должен приводить к бесконечному увеличению стоимости поиска.

---

# Principle 12

## Все компоненты независимы

Каждый модуль имеет одну ответственность.

Например:

Perception отвечает только за восприятие.

Memory отвечает только за хранение.

Reasoning отвечает только за выводы.

Planner отвечает только за выбор действий.

Execution отвечает только за выполнение.

Critic отвечает только за оценку.

Ни один компонент не должен выполнять функции другого.

---

# Principle 13

## Любая подсистема может быть заменена

Любой компонент может быть полностью переписан.

При этом остальные подсистемы продолжат работать.

Архитектура важнее реализации.

---

# Principle 14

## Производительность достигается архитектурой

Производительность должна обеспечиваться правильной архитектурой.

Не допускается усложнение архитектуры ради локальной оптимизации.

Оптимизация выполняется только после появления измеримых проблем.

---

# Principle 15

## Простота предпочтительнее сложности

Если две архитектуры дают одинаковый результат, выбирается более простая.

Минимальное количество сущностей предпочтительнее большого количества специализированных компонентов.

---

# Principle 16

## Любая новая возможность должна усиливать существующую архитектуру

Новые функции не должны появляться как исключения.

Каждая новая возможность должна естественным образом вписываться в существующую систему.

Если для реализации новой функции приходится нарушать существующие принципы, архитектура должна быть пересмотрена.

---

# Заключение

Данные принципы являются фундаментом проекта.

Все последующие документы должны соответствовать этим правилам.

Никакая реализация не может считаться правильной, если она противоречит данным принципам.
