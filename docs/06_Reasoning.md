# Reasoning

Version: 1.0

---

# Назначение

Reasoning является подсистемой мышления NeuroCore.

Его задача — преобразовывать существующие знания в новые знания.

Reasoning не получает информацию из внешнего мира.

Reasoning не работает с текстом, PDF, HTML, изображениями или другими исходными источниками.

Он работает исключительно с Knowledge Objects, находящимися в Memory и Working Memory.

---

# Главная задача

Используя существующие знания:

- делать выводы;
- находить закономерности;
- обнаруживать противоречия;
- строить гипотезы;
- выбирать алгоритмы;
- объяснять собственные выводы.

---

# Главный принцип

Reasoning никогда не создаёт знания "из ничего".

Любой вывод обязан иметь происхождение.

Каждый новый объект знаний должен содержать ссылки на объекты, которые использовались для его построения.

Если происхождение невозможно определить, вывод считается недостоверным.


---

# Входные данные

Reasoning получает:

- Goal;
- Working Memory;
- ограничения;
- активные алгоритмы;
- текущий контекст.

Reasoning никогда самостоятельно не ищет информацию во всей памяти.

Working Memory уже содержит необходимые знания.

---

# Выходные данные

Reasoning может создавать:

- Fact;
- Rule;
- Hypothesis;
- Prediction;
- Algorithm;
- Relation;
- Goal;
- Question;
- Constraint.

Все результаты сохраняются через Memory API.

---

# Стратегии мышления

Reasoning состоит из независимых механизмов.

---

# Deduction

Дедукция выводит частный вывод из общих знаний.

Пример

```
Все птицы имеют крылья.

Ворон — птица.

↓

Ворон имеет крылья.
```

Дедукция должна давать только логически корректные выводы.

---

# Induction

Индукция строит обобщение.

Пример

```
100 наблюдений

↓

Закономерность

↓

Новое правило
```

Индукция всегда имеет уровень уверенности.

Полученный результат никогда не считается абсолютной истиной.

---

# Abduction

Абдукция ищет наиболее вероятное объяснение.

Пример

```
Компьютер выключился.

↓

Возможные причины.

↓

Наиболее вероятная причина.
```

Абдукция создаёт Hypothesis.

---

# Analogy

Аналогия переносит знания между похожими объектами.

Пример

```
Git

похож на

Version Control

↓

Использовать похожие знания.
```

Аналогия никогда не создаёт Fact напрямую.

Она создаёт только Hypothesis.

---

# Causality

Определяет причинно-следственные связи.

Например

```
Переполнение памяти

↓

Crash
```

или

```
Изменение конфигурации

↓

Ускорение системы
```

---

# Constraint Reasoning

Работает с ограничениями.

Например

```
Нельзя делить на ноль.

↓

Все планы, нарушающие правило,

отбрасываются.
```

---

# Simulation

Позволяет моделировать последствия действий.

```
Current State

↓

Possible Action

↓

Predicted State
```

Simulation не изменяет Memory.

Он работает только с копиями Working Memory.

---

# Reflection

Reflection анализирует собственное мышление.

Он отвечает на вопросы:

- правильно ли выбрана стратегия;
- были ли ошибки;
- существуют ли лучшие решения;
- достаточно ли знаний.

Reflection может породить новые Question.

---

# Validation

Перед сохранением вывод проходит проверку.

Проверяется:

- логическая корректность;
- отсутствие противоречий;
- происхождение;
- уровень доверия;
- полнота объяснения.

---

# Выбор стратегии

Reasoning не использует всегда один и тот же механизм.

Он выбирает стратегию в зависимости от задачи.

Например

```
Question

↓

Strategy Selection

↓

Deduction

или

Analogy

или

Simulation

или

Abduction
```

Стратегии могут комбинироваться.

---

# Объяснимость

Каждый вывод обязан иметь объяснение.

Минимальное объяснение включает:

- использованные знания;
- использованные правила;
- последовательность шагов;
- уровень уверенности.

Explanation сохраняется вместе с результатом.

---

# Работа с неопределённостью

Reasoning допускает существование неопределённости.

Например

```
Несколько возможных объяснений.

Несколько возможных планов.

Несколько возможных выводов.
```

Вместо выбора одного ответа Reasoning может вернуть несколько вариантов с различной уверенностью.

---

# Ошибки

Ошибочные выводы не удаляются автоматически.

Они сохраняются как Error и Experience.

Learning использует ошибки для изменения будущих стратегий.

---

# Взаимодействие с Learning

Learning анализирует результаты работы Reasoning.

Он может:

- повысить доверие к стратегии;
- понизить доверие;
- изменить статистику;
- предложить новую стратегию;
- отключить неэффективную стратегию.

Сам Reasoning не обучается.

Он использует знания, подготовленные Learning.

---

# Взаимодействие с Planner

Reasoning не строит планы.

Он помогает Planner.

Например:

- оценивает варианты;
- прогнозирует последствия;
- проверяет ограничения;
- объясняет риски.

Planner принимает окончательное решение.

---

# Взаимодействие с Memory

Reasoning не изменяет память напрямую.

Все новые знания передаются через Memory API.

Memory отвечает за:

- сохранение;
- объединение;
- индексацию;
- историю;
- связи.

---

# Производительность

Reasoning никогда не работает со всей Memory.

Он использует только Working Memory.

Это обеспечивает:

- предсказуемое время работы;
- масштабируемость;
- возможность хранить миллионы знаний.

---

# Инварианты

Reasoning обязан соблюдать следующие правила.

- Работает только с Knowledge Objects.
- Не обращается к исходным данным.
- Не изменяет Memory напрямую.
- Каждый вывод имеет происхождение.
- Каждый вывод имеет объяснение.
- Любая гипотеза имеет уровень доверия.
- Ошибки являются знаниями.
- Все результаты сохраняются через Memory API.

---

# Заключение

Reasoning является интеллектуальным ядром NeuroCore.

Он не хранит знания и не получает информацию из внешнего мира.

Его задача — использовать уже существующие знания для построения новых выводов, объяснять процесс собственного мышления и передавать результаты обратно в Memory для дальнейшего обучения системы.
