# Memory

Version: 1.0

---

# Назначение

Memory является центральной подсистемой NeuroCore.

Все остальные подсистемы существуют вокруг памяти.

Memory не является базой данных.

Memory не является графом.

Memory не является кэшем.

Memory является когнитивной памятью системы.

Её задача — хранить, организовывать, связывать, активировать и постепенно изменять знания.

---

# Главная цель

Memory должна обеспечивать возможность системе:

- помнить;
- понимать связи;
- использовать прошлый опыт;
- обучаться;
- забывать;
- объяснять свои решения;
- быстро находить необходимые знания;
- масштабироваться без изменения архитектуры.

---

# Что НЕ является задачей Memory

Memory не должна:

- понимать текст;
- анализировать изображения;
- выполнять дедукцию;
- строить планы;
- выполнять действия;
- обращаться к LLM;
- принимать решения.

Этим занимаются другие подсистемы.

Memory отвечает исключительно за работу со знаниями.

---

# Основная модель

Memory рассматривается как единое пространство знаний.

```
Memory

├── Knowledge Objects
│
├── Relations
│
├── Indexes
│
├── Statistics
│
├── Activation
│
├── History
│
└── Storage
```

Все компоненты являются частью одной подсистемы.

---

# Главные обязанности

Memory отвечает за:

- хранение объектов знаний;
- хранение связей;
- поиск знаний;
- индексацию;
- обновление знаний;
- удаление знаний;
- версионирование;
- распространение активации;
- статистику использования;
- историю изменений.

---

# Основной принцип

Memory ничего не знает о предметной области.

Она одинаково хранит:

- рецепты;
- математику;
- RFC;
- программный код;
- сетевые протоколы;
- химию;
- музыку.

Memory знает только структуру знаний.

Содержание её не интересует.

---

# Архитектура Memory

```
                Memory
                   │
    ┌──────────────┼──────────────┐
    │              │              │
Knowledge      Relations      Indexes
    │              │              │
    ├──────────────┼──────────────┤
                   │
            Activation Engine
                   │
            Statistics Engine
                   │
             History Engine
                   │
             Storage Backend
```

Каждый компонент имеет одну ответственность.

---

# Memory Layers

Memory разделяется на несколько логических уровней.

```
Application Layer

↓

Memory API

↓

Memory Engine

↓

Storage Engine
```

---

## Application Layer

Используется:

- Reasoning
- Planner
- Learning
- Execution
- Understanding

Они никогда не работают напрямую с LMDB.

---

## Memory API

Единственная точка входа.

Все операции проходят через API.

Например:

```
Find()

Store()

Update()

Delete()

Link()

Activate()

Search()

...
```

---

## Memory Engine

Отвечает за:

- проверку данных;
- работу индексов;
- активацию;
- обновление статистики;
- согласованность памяти.

---

## Storage Engine

Минимальный уровень.

Отвечает только за физическое хранение.

В текущей реализации используется LMDB.

В будущем может быть заменён.

---

# Виды памяти

Архитектура разделяет несколько логических видов памяти.

Они не являются разными базами данных.

Это различные способы использования Knowledge Objects.

```
Memory

├── Semantic Memory
├── Episodic Memory
├── Procedural Memory
├── Working Memory
├── Predictive Memory
└── Meta Memory
```

Все используют одну модель знаний.

---

# Semantic Memory

Содержит знания о мире.

Например:

- понятия;
- определения;
- факты;
- свойства;
- правила;
- отношения.

Именно Semantic Memory используется чаще всего.

---

# Episodic Memory

Хранит события.

Например:

- выполнение задачи;
- разговор;
- запуск программы;
- анализ книги;
- обучение;
- ошибка.

Episode связывает множество объектов знаний.

---

# Procedural Memory

Содержит способы выполнения задач.

Например:

- алгоритмы;
- процедуры;
- навыки;
- шаблоны решений.

Planner использует именно Procedural Memory.

---

# Working Memory

Working Memory не хранит знания.

Она содержит только активные ссылки на объекты долговременной памяти.

```
Long-term Memory

↓

Activation

↓

Working Memory

↓

Reasoning
```

После завершения задачи Working Memory очищается.

---

# Predictive Memory

Используется Learning.

Содержит:

- прогнозы;
- ожидания;
- вероятные результаты;
- статистические модели.

Prediction не является фактом.

---

# Meta Memory

Хранит знания о самой памяти.

Например:

- статистику;
- скорость поиска;
- эффективность алгоритмов;
- распределение типов знаний;
- информацию об индексах.

Meta Memory помогает системе оптимизировать собственную работу.

---

# Долговременная память

Long-Term Memory является основным хранилищем знаний.

Все объекты после Validation попадают именно сюда.

Долговременная память должна переживать:

- завершение процесса;
- перезапуск системы;
- обновление программы.

---

# Кратковременная память

Working Memory существует только во время выполнения задачи.

После завершения задачи она может быть полностью освобождена.

---

# Активная память

Не все знания используются одновременно.

Каждый объект имеет уровень активации.

Во время решения задачи активируются только необходимые объекты.

Активность постепенно уменьшается.

---

# Индексация

Memory обязана поддерживать несколько независимых индексов.

Минимальный набор:

- ID Index
- Type Index
- Name Index
- Relation Index
- Source Index
- Trust Index
- Time Index
- Tag Index

Конкретная реализация индексов определяется Storage Engine.

---

# Поиск

Memory предоставляет универсальный поиск.

Минимальные режимы:

- по идентификатору;
- по имени;
- по типу;
- по содержимому;
- по отношениям;
- по источнику;
- по времени;
- по доверию;
- по статистике;
- по семантической близости.

Все поисковые операции проходят через Memory API.

---

# Активация

Активация является одной из главных функций Memory.

Во время решения задачи:

```
Goal

↓

Activation

↓

Working Memory

↓

Reasoning
```

Memory самостоятельно определяет,

какие знания должны стать активными.

Reasoning не должен загружать всю память.

---

# Статистика

Каждый объект накапливает статистику.

Например:

- количество обращений;
- успешность;
- количество выводов;
- дата последнего использования;
- среднее время активации.

Learning использует эти данные для изменения памяти.

---

# История

История изменений хранится отдельно от основного объекта.

Это позволяет:

- анализировать развитие знаний;
- выполнять откат;
- объяснять решения;
- проводить аудит.

История не участвует в обычном поиске.

---

# Инварианты

Memory обязана гарантировать:

- отсутствие потери данных при корректном завершении работы;
- уникальность идентификаторов;
- целостность связей;
- согласованность индексов;
- сохранность истории;
- независимость от реализации хранилища;
- единый API для всех подсистем.

---

# Заключение

Memory является центральной подсистемой NeuroCore.

Она не принимает решений, не понимает текст и не выполняет рассуждений.

Её задача — предоставить остальным подсистемам надёжную, масштабируемую и согласованную модель хранения знаний, которая будет служить фундаментом для всех когнитивных процессов системы.
