# RFC-0002 — World Model (Internal Predictive Model)

## Статус

**Draft**

---

# Цель

Добавить в KOSMOS внутреннюю модель мира, позволяющую агенту:

* хранить состояние мира;
* понимать последствия действий;
* строить ожидания;
* сравнивать ожидания с реальностью;
* учиться на ошибках предсказаний;
* использовать модель мира для планирования.

RFC не изменяет NeuroAtom, HyperMemory, LMDB, VM или формат хранения.

Используются только существующие механизмы.

---

# Мотивация

Сегодня система знает факты.

```
SQL Injection
IS_A
Web Vulnerability
```

или

```
Kerberoasting

USES

TGS
```

Но этого недостаточно.

AGI должна понимать

```
если выполнить действие,

мир изменится.
```

То есть мыслить переходами состояний.

---

# Основная модель

Вся когнитивная деятельность строится вокруг одной схемы.

```
State

↓

Action

↓

Predicted State

↓

Observation

↓

Experience

↓

Belief Update
```

Это становится базовым циклом обучения.

---

# Определения

## State

Описание текущего мира.

Не структура C.

Обычный Entity.

Примеры

```
LoggedIn

DomainAdmin

DatabaseConnected

FirewallEnabled

UserAuthenticated

HostCompromised

```

---

## Action

Любое действие.

Например

```
RunAlgorithm

HTTPRequest

Exploit

ExecutePipeline

ReadFile

ConnectLDAP

```

Тоже обычная Entity.

---

## Transition

Связь

```
State

+

Action

↓

Next State
```

Хранится как обычные HyperAtom.

---

## Prediction

Ожидаемый результат.

Например

```
Current State

Authenticated

Action

Run Kerberoast

Prediction

Receive TGS
```

---

## Observation

То, что реально произошло.

---

## Experience

Сравнение Prediction и Observation.

```
Prediction

↓

Observation

↓

Experience
```

Experience становится входом RFC-0001.

---

## Belief

Experience обновляет Belief.

Belief обновляет Planner.

---

# Новые отношения онтологии

Это не новые ProcKind.

Не enum.

Не структуры.

Обычные Entity.

Например

```
STATE

ACTION

TRANSITION

PREDICTS

RESULTS_IN

EXPECTED

OBSERVED

HAS_EXPERIENCE

HAS_BELIEF

```

Они загружаются через bootstrap/perception.

---

# Planner

Planner больше не выбирает алгоритм напрямую.

Теперь цикл выглядит так.

```
Recall

↓

Predict

↓

Estimate Utility

↓

Estimate Belief

↓

Execute

↓

Experience

↓

Belief Update
```

---

# Prediction Error

Главная величина обучения.

```
Prediction

!=

Observation
```

Если совпало

↓

Belief растет.

Если нет

↓

Belief падает.

Prediction Error сохраняется как Experience.

---

# Curiosity

Curiosity появляется автоматически.

Если

```
Prediction Error

большой
```

создается

```
Research Goal
```

Например

```
Почему это произошло?
```

или

```
Найти лучшее объяснение.
```

---

Planner использует

# Что будет после RFC-0002

После этого я бы **не переходил сразу к Curiosity**.

Логичнее строить следующий фундамент в таком порядке:

* **RFC-0003 — Reasoning Engine** (дедукция, индукция, абдукция, аналогия, backward chaining поверх World Model).
* **RFC-0004 — Research Engine** (цикл Hypothesis → Experiment → Experience → Belief).
* **RFC-0005 — Knowledge Ingestion** (Python-парсер книг/статей → IPC → HyperAtom, без LLM в рантайме).
* **RFC-0006 — Skill & Program Learning** (накопление и композиция алгоритмов, синтез новых пайплайнов).

Такая последовательность, на мой взгляд, наиболее устойчива: сначала агент учится моделировать мир, затем рассуждать о нем, затем исследовать его, затем быстро наполняться знаниями, и только после этого — самостоятельно наращивать навыки. Это хорошо согласуется с той архитектурой, которую вы уже зафиксировали в RFC-0001.
