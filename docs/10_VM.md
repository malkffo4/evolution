# VM

Version: 2.1

---

# Назначение

VM (Virtual Mind) — центральная исполнительная среда NeuroCore.

Важно различать два независимых уровня исполнения.

1. **Virtual Mind** — когнитивный координатор системы.
2. **Instruction VM** — низкоуровневый исполнитель Pipeline.

Именно совместная работа этих компонентов образует исполнительное ядро NeuroCore.

---

# Два уровня исполнения

Архитектура NeuroCore разделяет интеллект и выполнение.

```
                 Goal

                  │

            Reasoning

                  │

             Planning

                  │

        Runtime Compiler

                  │

          Pipeline (IR)

                  │

          Instruction VM

                  │

        Native Dispatch Table

                  │

        Native Operations

                  │

          Operating System
```

Интеллект принимает решения.

Instruction VM их исполняет.

---

# Virtual Mind

Virtual Mind — это исполнительная когнитивная среда.

Она отвечает за организацию процесса мышления.

Virtual Mind ничего не знает о конкретных инструкциях Pipeline.

Она работает только с высокоуровневыми сущностями.

Например:

- Goal;
- Context;
- Task;
- Thought;
- Working Memory;
- Attention;
- Blackboard;
- Planner;
- Learning.

Virtual Mind управляет жизненным циклом всей когнитивной системы.

---

# Instruction VM

Instruction VM — это низкоуровневый исполнитель.

Она похожа на процессор.

Instruction VM ничего не знает о:

- знаниях;
- графовой базе;
- аналогиях;
- гипотезах;
- целях;
- правилах;
- памяти;
- обучении.

Она умеет только выполнять Pipeline.

---

# Главный принцип

Интеллект никогда не находится внутри Instruction VM.

Он всегда находится выше.

```
Knowledge

↓

Reasoning

↓

Planner

↓

Compiler

↓

Pipeline

↓

Instruction VM
```

Instruction VM не принимает решений.

Она исполняет уже подготовленный план.

# Virtual Mind отвечает за

- Goal Management;
- Context Management;
- Scheduler;
- Task Manager;
- Attention;
- Blackboard;
- запуск Reasoning;
- запуск Planner;
- запуск Compiler;
- запуск Learning;
- передачу Pipeline на исполнение;
- анализ результата выполнения.

---

# Instruction VM отвечает за

- выполнение Pipeline;
- регистры;
- локальное состояние исполнения;
- стек вызовов;
- вызов Native Operations;
- возврат результата;
- сбор профиля выполнения (VMProfile).

Больше ничего.

---

# Runtime Pipeline

Типичный цикл работы системы выглядит следующим образом.

```
Goal

↓

Reasoning

↓

Planner

↓

Compiler

↓

Pipeline (IR)

↓

Instruction VM

↓

Execution Result

↓

Virtual Mind

↓

Learning
```

Instruction VM никогда не обращается к Planner напрямую.

---

# Pipeline

Pipeline представляет собой внутреннее промежуточное представление программы (IR).

Он создаётся Runtime Compiler на основе результата работы Planner.

Pipeline является полностью детерминированной последовательностью инструкций.

Например

```
LOAD_CONST

↓

CALL

↓

STORE

↓

BRANCH

↓

HALT
```

Instruction VM последовательно выполняет эти инструкции.

---

# Runtime Compiler

Компилятор является мостом между интеллектом и исполнением.

Он:

- получает план от Planner;
- разрешает ссылки;
- выбирает реализации операций;
- связывает Capability с Native Operations;
- строит Pipeline;
- формирует Dispatch Table.

После завершения компиляции Pipeline становится полностью автономным.

Instruction VM ничего не компилирует.

---

# Native Dispatch Table

Во время компиляции создаётся таблица диспетчеризации.

```
Opcode

↓

Native Function
```

Например

```
LOAD_CONST

↓

op_load_const

CALL

↓

op_call

STORE

↓

op_store
```

Instruction VM выполняет инструкции исключительно через эту таблицу.

Никаких поисков по имени во время исполнения не происходит.

---

# Capability и Native Operations

Planner работает с абстрактными возможностями системы (**Capability**).

Например

```
ReadFile

SearchGraph

CallLLM

WriteFile
```

Во время компиляции каждая Capability связывается с конкретной реализацией.

Например

```
ReadFile

↓

op_read_file_linux()

или

↓

op_read_file_windows()
```

Таким образом одна Capability может иметь несколько платформенных реализаций.

Instruction VM всегда работает только с уже выбранной Native Operation.

---

# Operator Registry

Все Native Operations регистрируются заранее.

Например

```
operator_registry_init()
```

Регистрация создаёт отображение

```
Opcode

↓

Native Operation
```

Instruction VM использует только зарегистрированные операции.

Во время исполнения новые операции не ищутся и не создаются.

---

# System Knowledge

Знания о возможностях системы находятся в Knowledge.

Например

- POSIX API;
- Linux Syscalls;
- libc;
- IPC;
- Plugins;
- внутренние сервисы;
- Runtime API.

Эти знания используются:

- Parser;
- Reasoning;
- Planner;
- Compiler.

Instruction VM ничего об этом не знает.

Она получает уже готовые вызовы.

---

# Working Memory

Working Memory принадлежит Virtual Mind.

Она содержит только ссылки на активные знания.

Instruction VM не управляет Working Memory.

Она получает только необходимые данные через Context.

---

# Context

Context существует только на уровне Virtual Mind.

Он содержит

- текущую Goal;
- ограничения;
- активные знания;
- параметры задачи;
- промежуточные результаты;
- параметры исполнения Pipeline.

Instruction VM получает лишь необходимые данные.

---

# Scheduler

Scheduler определяет порядок запуска компонентов.

Например

```
Reasoning

↓

Planner

↓

Compiler

↓

Instruction VM

↓

Learning
```

Scheduler не принимает логических решений.

Он только распределяет выполнение.

---

# Blackboard

Blackboard существует только внутри Virtual Mind.

На ней временно размещаются

- гипотезы;
- промежуточные выводы;
- планы;
- результаты анализа.

После завершения задачи Blackboard очищается.

Instruction VM никогда не взаимодействует с Blackboard.

---

# Runtime State

Virtual Mind имеет глобальное состояние.

Например

```
Idle

Thinking

Planning

Compiling

Executing

Learning

Waiting

Paused

Stopped
```

Во время состояния **Executing** управление передаётся Instruction VM.

---

# VM Profile

Instruction VM во время исполнения собирает профиль выполнения.

Например

- количество выполненных инструкций;
- время исполнения;
- количество вызовов операций;
- статистику ветвлений;
- ошибки;
- использование памяти.

VMProfile возвращается Virtual Mind.

Planner и Learning могут использовать его для последующей оптимизации.

---

# Events

Все события проходят через Virtual Mind.

Например

```
GoalCreated

TaskStarted

PipelineCompiled

ExecutionStarted

ExecutionFinished

GoalCompleted

LearningStarted

Shutdown
```

Instruction VM сообщает только события исполнения.

---

# Работа с ошибками

Instruction VM может вернуть

- Success;
- Runtime Error;
- Invalid Opcode;
- Invalid Register;
- Access Violation;
- Stack Overflow;
- Timeout.

Virtual Mind преобразует их в события системы.

Например

```
Execution Error

↓

Event

↓

Episode

↓

Learning
```

Ошибки никогда не игнорируются.

---

# Производительность

Instruction VM должна оставаться максимально простой.

Её требования:

- детерминированность;
- высокая скорость;
- минимальное количество ветвлений;
- отсутствие когнитивной логики;
- отсутствие обращений к Graph Database;
- отсутствие поиска знаний во время исполнения.

Все интеллектуальные вычисления выполняются до запуска Pipeline.

---

# Инварианты

## Virtual Mind

Virtual Mind обязана соблюдать следующие правила.

- Все знания находятся только в Memory.
- Все когнитивные процессы проходят через Virtual Mind.
- Working Memory содержит только ссылки.
- Все подсистемы взаимодействуют через Virtual Mind.
- Каждый Goal имеет Context.
- Каждый Pipeline принадлежит одной задаче.
- Все события журналируются.
- Все результаты передаются через Memory API.

## Instruction VM

Instruction VM обязана соблюдать следующие правила.

- Выполнять только Pipeline.
- Никогда не обращаться к Graph Database.
- Никогда не выполнять поиск знаний.
- Никогда не принимать когнитивных решений.
- Использовать только зарегистрированные Native Operations.
- Работать только через Dispatch Table.
- Возвращать детерминированный результат.
- Формировать VMProfile после завершения исполнения.

---

# Заключение

В NeuroCore термин **VM** обозначает два взаимосвязанных уровня.

**Virtual Mind** — когнитивный координатор системы. Он управляет целями, вниманием, рабочей памятью, рассуждением, планированием, компиляцией и обучением.

**Instruction VM** — низкоуровневый исполнитель Pipeline. Он не обладает интеллектом, не работает с графовой памятью и не принимает решений. Его задача — быстро, детерминированно и эффективно выполнить уже подготовленный Pipeline с использованием заранее зарегистрированных Native Operations.

Такое разделение позволяет независимо развивать когнитивную архитектуру и исполнительное ядро. Интеллект системы может становиться всё сложнее, не влияя на производительность Instruction VM, а исполнитель остаётся простым, быстрым и предсказуемым.
