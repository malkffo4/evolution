# VM

Version: 1.0

---

# Назначение

VM (Virtual Mind) является исполнительной когнитивной средой NeuroCore.

Это не виртуальная машина байткода.

Это не JVM.

Это не Lua VM.

Это внутренняя среда, внутри которой выполняются процессы мышления.

Все когнитивные процессы происходят именно внутри VM.

---

# Главная задача

Обеспечить единое пространство выполнения для:

- Reasoning;
- Planner;
- Execution;
- Learning;
- Attention;
- Working Memory.

VM координирует их работу.

---

# Главный принцип

Memory хранит знания.

VM работает со знаниями.

Memory отвечает на вопрос

> Что известно?

VM отвечает на вопрос

> Что происходит прямо сейчас?

---

# VM как "рабочее сознание"

Можно представить архитектуру следующим образом.

```
Long-Term Memory

↓

Activation

↓

Working Memory

↓

VM

↓

Reasoning

↓

Planner

↓

Execution
```

VM не хранит долговременные знания.

Она управляет текущим процессом мышления.

---

# Архитектура

```
                    VM

             Scheduler

                     │

    ┌────────────────┼────────────────┐

    │                │                │

Working Memory   Thought Engine   Goal Stack

    │                │                │

    └────────────────┼────────────────┘
```

---

# VM отвечает за

- текущий контекст;
- выполнение мыслительных процессов;
- управление задачами;
- переключение внимания;
- жизненный цикл целей;
- рабочую память;
- координацию подсистем.

---

# VM НЕ отвечает за

- хранение знаний;
- понимание документов;
- обучение;
- долговременную память;
- построение базы знаний.

---

# Runtime

Каждый момент времени VM находится в некотором Runtime State.

Например

```
Idle

Thinking

Planning

Executing

Learning

Waiting

Paused

Stopped
```

Одновременно существует только одно глобальное состояние VM.

---

# Context

Context описывает всё, что относится к текущей задаче.

Он включает

- Goal;
- активные Knowledge Objects;
- активные ограничения;
- текущие результаты;
- активные переменные;
- историю текущего процесса.

Context существует только во время выполнения задачи.

---

# Working Memory

Working Memory принадлежит VM.

Она содержит ссылки на активные объекты Memory.

Working Memory никогда не копирует знания.

Она содержит только идентификаторы и временное состояние.

---

# Thought

Thought является минимальной единицей мышления.

Например

```
Получить знание.

Проверить правило.

Построить аналогию.

Вывести гипотезу.

Проверить ограничение.
```

Любой процесс мышления состоит из последовательности Thought.

---

# Thought Pipeline

```
Input

↓

Evaluate

↓

Transform

↓

Output
```

Каждый Thought может создавать новые Thought.

---

# Goal Stack

VM поддерживает стек целей.

Например

```
Goal A

↓

Goal B

↓

Goal C
```

После завершения Goal C выполнение возвращается к Goal B.

Это позволяет поддерживать вложенные задачи.

---

# Task Manager

Task Manager управляет всеми активными задачами.

Каждая задача имеет состояние.

Например

```
Created

Ready

Running

Waiting

Completed

Failed

Cancelled
```

---

# Scheduler

Scheduler определяет,

какой компонент должен выполняться следующим.

Например

```
Reasoning

↓

Planner

↓

Execution

↓

Learning
```

Scheduler не принимает логических решений.

Он только распределяет выполнение.

---

# Attention Engine

Attention отвечает за распределение вычислительных ресурсов.

Невозможно одновременно анализировать всю память.

Attention определяет,

какие объекты Working Memory являются наиболее важными.

---

# Focus

Focus представляет множество объектов,

на которых сейчас сосредоточена система.

Например

```
Goal

+

Rule

+

Algorithm

+

Current Observation
```

Reasoning работает только с Focus.

---

# Attention Score

Каждый активный объект имеет оценку внимания.

На неё влияют

- Goal;
- новизна;
- доверие;
- недавнее использование;
- важность;
- вероятность использования.

Attention постоянно пересчитывается.

---

# Blackboard

VM содержит внутреннюю рабочую доску.

На ней временно размещаются

- промежуточные выводы;
- гипотезы;
- результаты вычислений;
- временные структуры.

После завершения задачи Blackboard очищается.

---

# Events

VM полностью событийно-ориентирована.

Основные события

```
GoalCreated

GoalCompleted

TaskStarted

TaskFinished

KnowledgeActivated

KnowledgeUpdated

ThoughtCreated

ThoughtFinished

ErrorOccurred

Timeout

Shutdown
```

Все события журналируются.

---

# State Machine

VM работает как конечный автомат.

```
Idle

↓

Thinking

↓

Planning

↓

Executing

↓

Learning

↓

Idle
```

Возможны переходы в

```
Waiting

Paused

Cancelled

Failed
```

---

# Resource Management

VM отвечает за управление ресурсами.

Например

- память;
- время;
- количество активных задач;
- глубина рассуждений;
- максимальный размер Working Memory.

Это предотвращает бесконтрольный рост вычислений.

---

# Ограничение глубины

Чтобы избежать бесконечных рассуждений,

VM контролирует

- глубину вывода;
- глубину рекурсии;
- количество Thought;
- время выполнения.

При превышении лимитов задача приостанавливается.

---

# IPC

VM является центральным маршрутизатором сообщений.

Подсистемы не должны обращаться друг к другу напрямую.

Например

```
Reasoning

↓

VM

↓

Planner
```

а не

```
Reasoning

↓

Planner
```

Это уменьшает связанность системы.

---

# Работа с ошибками

Любая ошибка внутри VM становится событием.

Например

```
Error

↓

Event

↓

Episode

↓

Learning
```

Ошибки никогда не игнорируются.

---

# Завершение задачи

После завершения Goal VM:

- очищает Blackboard;
- освобождает Working Memory;
- завершает Task;
- создаёт Episode;
- передаёт результаты Memory;
- запускает Learning при необходимости.

---

# Производительность

VM должна поддерживать:

- многопоточность;
- асинхронность;
- масштабирование;
- минимальное количество блокировок;
- детерминированное выполнение.

---

# Инварианты

VM обязана соблюдать следующие правила.

- Все знания находятся только в Memory.
- Working Memory содержит только ссылки.
- Все процессы выполняются внутри VM.
- Подсистемы взаимодействуют через VM.
- Каждая задача имеет Context.
- Каждая цель имеет жизненный цикл.
- Каждый Thought принадлежит одной задаче.
- Все события журналируются.
- Все результаты сохраняются через Memory API.

---

# Заключение

VM является исполнительным ядром NeuroCore.

Она не хранит знания и не принимает интеллектуальные решения самостоятельно.

Её задача — предоставить единую среду выполнения, в которой координируются все когнитивные процессы системы: внимание, рабочая память, рассуждение, планирование, выполнение и обучение.

Именно VM превращает набор отдельных модулей в единую когнитивную архитектуру.
