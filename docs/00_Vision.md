# Vision

Version: 1.0

---

# Цель проекта

NeuroCore — это проект по созданию универсального когнитивного ядра.

Под когнитивным ядром понимается система, которая способна:

- воспринимать информацию;
- понимать её содержание;
- превращать информацию в знания;
- хранить знания;
- извлекать знания;
- рассуждать;
- принимать решения;
- планировать действия;
- выполнять действия;
- оценивать результаты;
- обучаться на собственном опыте.

Проект не является очередной языковой моделью.

Языковые модели рассматриваются лишь как один из возможных инструментов системы.

Главным объектом проекта является память.

Именно память должна стать источником интеллекта.

---

# Главная идея

Современные ИИ в основном строятся вокруг моделей.

NeuroCore строится вокруг памяти.

Не модель определяет возможности системы.

Именно накопленные знания определяют качество её мышления.

Поэтому память рассматривается как главный долгоживущий компонент проекта.

Любые модели могут быть заменены без потери накопленных знаний.

---

# Что такое знание

Проект рассматривает знания как внутреннее представление информации.

Источник информации не имеет значения.

Это может быть:

- книга;
- статья;
- документация;
- RFC;
- исходный код;
- разговор;
- изображение;
- видео;
- наблюдение;
- собственный опыт.

После обработки любой источник должен быть преобразован в единый формат знаний.

Все дальнейшие компоненты работают только с этим внутренним представлением.

---

# Главный цикл системы

Работа системы представляет собой непрерывный цикл.

```
Восприятие

↓

Понимание

↓

Компиляция знаний

↓

Память

↓

Рассуждение

↓

Планирование

↓

Выполнение

↓

Оценка результата

↓

Обучение

↓

Память
```

Этот цикл никогда не заканчивается.

Каждое новое наблюдение увеличивает общий объём знаний системы.

Каждый новый опыт способен изменить будущие решения.

---

# Главная цель памяти

Память не является архивом.

Память является активной частью мышления.

Она должна:

- хранить знания;
- связывать знания;
- забывать несущественное;
- усиливать важное;
- поддерживать ассоциации;
- помогать рассуждению;
- использовать прошлый опыт при принятии решений.

Без памяти невозможно обучение.

Без обучения невозможно накопление интеллекта.

---

# Главная цель рассуждения

Рассуждение не создаёт знания.

Оно использует знания.

Любой механизм рассуждения обязан работать исключительно через память.

Если алгоритм не может быть описан как работа над знаниями, значит он нарушает архитектуру.

---

# Главная цель обучения

Обучение не означает изменение весов модели.

Обучение означает изменение памяти.

После получения новой информации система должна:

- сохранить новые знания;
- пересмотреть существующие знания;
- обнаружить противоречия;
- скорректировать уровень доверия;
- сформировать новые связи;
- при необходимости изменить способы решения задач.

---

# Главная цель планирования

Планирование преобразует цели в последовательность действий.

Планировщик не содержит знаний предметной области.

Он использует знания, уже находящиеся в памяти.

---

# Главная цель выполнения

Исполнитель не принимает решений.

Он реализует выбранный план.

После выполнения результаты возвращаются обратно в память.

---

# Главная цель критики

Каждое выполненное действие должно быть оценено.

Результат оценки используется для изменения памяти.

Ошибки являются источником обучения.

Неудачные решения не удаляются.

Они становятся опытом.

---

# Главная цель проекта

Конечной целью проекта является создание системы, которая способна непрерывно увеличивать собственную способность решать задачи за счёт накопления, организации и повторного использования знаний.

Рост возможностей системы должен происходить не вследствие увеличения размера модели, а вследствие улучшения структуры памяти и накопленного опыта.

---

# Что не является целью проекта

Проект не ставит своей целью:

- имитацию человека;
- создание сознания;
- моделирование эмоций как самоцели;
- создание универсальной языковой модели;
- соревнование с существующими LLM.

Любая технология рассматривается только с точки зрения её пользы для когнитивной архитектуры.

---

# Архитектурный принцип

Любой компонент системы должен отвечать на три вопроса.

1. Какие знания он получает?

2. Какие знания он создаёт?

3. Какие знания он изменяет?

Если компонент невозможно описать через эти три вопроса, значит его место в архитектуре требует пересмотра.

---

# Основной критерий качества

Архитектурные решения принимаются не по критерию скорости разработки.

Они принимаются по критерию долгосрочной расширяемости.

Любая подсистема должна иметь возможность быть полностью заменённой без необходимости переписывать остальные компоненты.

---

# Видение проекта

Проект должен постепенно эволюционировать в когнитивную платформу, способную самостоятельно накапливать знания, развивать внутренние модели предметных областей, строить новые связи между ними и использовать накопленный опыт для решения ранее неизвестных задач.

Этот путь рассматривается как длительный инженерный процесс, а не как попытка воспроизвести человеческий интеллект целиком.
