# Planner

Version: 1.0

---

# Назначение

Planner отвечает за преобразование целей в выполнимые планы.

Planner не думает вместо Reasoning.

Planner не понимает текст.

Planner не анализирует PDF.

Planner не извлекает знания.

Planner получает уже подготовленные знания и строит последовательность действий для достижения цели.

---

# Главная задача

Преобразовать Goal в один или несколько исполнимых планов.

```
Goal

↓

Planner

↓

Plan

↓

Execution
```

---

# Главный принцип

Planner никогда не принимает решения на основе "интуиции".

Любое действие должно быть обосновано знаниями, алгоритмами и ограничениями, находящимися в Memory.

Если знаний недостаточно — Planner должен вернуть Question или запросить дополнительную информацию.

---

# Ответственность Planner

Planner отвечает за:

- анализ цели;
- декомпозицию целей;
- поиск возможных способов решения;
- выбор наиболее подходящего алгоритма;
- проверку ограничений;
- оценку стоимости плана;
- построение нескольких альтернатив;
- передачу плана в Execution.

Planner не отвечает за выполнение плана.

---

# Архитектура

```
Goal

↓

Planner

├── Goal Analyzer
├── Context Builder
├── Algorithm Selector
├── Plan Generator
├── Constraint Checker
├── Cost Estimator
├── Risk Analyzer
├── Plan Optimizer
└── Plan Validator

↓

Plan

↓

Execution
```

Каждый модуль имеет одну ответственность.

---

# Общий цикл

```
Получение Goal

↓

Получение контекста

↓

Поиск алгоритмов

↓

Построение кандидатов

↓

Проверка ограничений

↓

Оценка стоимости

↓

Оптимизация

↓

Выбор лучшего плана

↓

Передача Execution
```

---

# Входные данные

Planner получает:

- Goal;
- Working Memory;
- доступные Algorithm;
- Procedure;
- Constraint;
- текущий контекст;
- доступные ресурсы.

Planner не обращается напрямую к Long-Term Memory.

Все необходимые знания уже находятся в Working Memory.

---

# Выходные данные

Planner создаёт объект типа Plan.

Plan содержит:

- последовательность действий;
- зависимости;
- необходимые ресурсы;
- ожидаемый результат;
- риски;
- оценку стоимости;
- вероятность успеха.

---

# Goal Analyzer

Первый этап Planner.

Разбирает Goal.

Определяет:

- конечное состояние;
- критерии успеха;
- ограничения;
- приоритет;
- дедлайн (если существует).

---

# Context Builder

Строит контекст задачи.

Получает из Working Memory только знания, относящиеся к текущей цели.

Удаляет всё лишнее.

Минимизирует объём данных.

---

# Algorithm Selector

Выбирает подходящие алгоритмы.

Например

```
Goal

↓

Sort Array

↓

QuickSort
MergeSort
HeapSort
```

или

```
Goal

↓

Reverse Engineering

↓

Static Analysis
Dynamic Analysis
Hybrid Analysis
```

Planner может выбрать несколько кандидатов.

---

# Plan Generator

Создаёт один или несколько вариантов решения.

Например

```
Goal

↓

Plan A

Plan B

Plan C
```

Каждый план независим.

---

# Constraint Checker

Проверяет выполнение ограничений.

Например

- время;
- память;
- права доступа;
- зависимости;
- последовательность действий;
- безопасность.

Планы, нарушающие обязательные ограничения, отклоняются.

---

# Cost Estimator

Оценивает стоимость выполнения.

Стоимость может включать:

- время;
- память;
- вычисления;
- сетевые запросы;
- стоимость API;
- вероятность ошибки.

Стоимость используется только для сравнения планов.

---

# Risk Analyzer

Оценивает риски.

Например

- вероятность неудачи;
- отсутствие данных;
- противоречивые знания;
- низкое доверие к алгоритму;
- высокая неопределённость.

Каждый риск получает собственную оценку.

---

# Plan Optimizer

Оптимизирует план.

Например

- удаляет лишние шаги;
- объединяет операции;
- изменяет порядок;
- уменьшает стоимость;
- уменьшает риски.

Оптимизация не должна изменять смысл Goal.

---

# Plan Validator

Последний этап.

Проверяет:

- достижима ли цель;
- отсутствуют ли циклы;
- существуют ли все зависимости;
- все ли ресурсы доступны;
- является ли план исполнимым.

Только после успешной проверки Plan может быть передан Execution.

---

# Структура Plan

Концептуально Plan состоит из:

```
Plan

├── Goal
├── Steps
├── Dependencies
├── Constraints
├── Resources
├── Risks
├── Cost
├── Confidence
├── Expected Result
└── Explanation
```

Plan также является Knowledge Object.

Он может храниться в Memory.

---

# Step

Шаг плана является самостоятельным объектом.

Каждый Step содержит:

- идентификатор;
- описание действия;
- входные данные;
- ожидаемый результат;
- необходимые ресурсы;
- список зависимостей.

Planner работает со Step как с графом зависимостей, а не как с линейным списком.

---

# Ветвления

План может содержать альтернативные пути.

Например

```
Step A

↓

если успешно

↓

Step B

иначе

↓

Step C
```

Planner поддерживает условные переходы.

---

# Параллелизм

Planner может определять независимые шаги.

Например

```
A

├── B
├── C
└── D

↓

E
```

Execution может выполнять такие шаги параллельно.

---

# Неудача выполнения

Если Execution сообщает о неудаче,

Planner не обязан строить план заново.

Он может:

- скорректировать текущий;
- выбрать альтернативный;
- запросить новые знания;
- вернуть ошибку.

---

# Повторное использование

Планы являются знаниями.

Если аналогичная задача уже решалась,

Planner может использовать существующий Plan как основу.

Learning постепенно повышает доверие к успешным планам.

---

# Взаимодействие с Reasoning

Reasoning помогает Planner.

Например:

- предлагает гипотезы;
- оценивает последствия;
- строит прогнозы;
- проверяет логическую корректность.

Planner остаётся ответственным за построение плана.

---

# Взаимодействие с Execution

Planner никогда не выполняет действия.

После создания Plan он передаёт его Execution.

Execution сообщает:

- успешность;
- ошибки;
- новые знания;
- изменения среды.

---

# Взаимодействие с Learning

Learning анализирует результаты выполнения планов.

Он может:

- повысить доверие к плану;
- понизить доверие;
- изменить стоимость;
- скорректировать оценку риска;
- рекомендовать альтернативные алгоритмы.

---

# Инварианты

Planner обязан соблюдать следующие правила.

- Работает только с Knowledge Objects.
- Не изменяет Memory напрямую.
- Не выполняет действия.
- Может создавать несколько альтернативных планов.
- Каждый план имеет объяснение.
- Каждый план имеет оценку стоимости.
- Каждый план имеет оценку риска.
- Каждый план проходит обязательную проверку.
- Все результаты сохраняются через Memory API.

---

# Заключение

Planner является подсистемой принятия решений.

Он преобразует цели в исполнимые планы, используя знания, алгоритмы, ограничения и опыт, накопленные в Memory.

Planner не выполняет действия и не получает знания напрямую из внешнего мира.

Его задача — выбрать наиболее эффективный путь достижения цели и передать его Execution.
