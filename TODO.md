- **Python-мозг** (отдельные процессы/сервисы):

  - Извлечение фактов/фреймов/эпизодов через LLM

# Как проверить, что архитектура способна к обучению пентесту и генерации нового

Сделай простой тест. Загрузи в систему описания 10 различных атак (из твоих книг). Затем спроси: «Как атаковать технологию X, если у неё есть свойство Y?» — причём такой комбинации не было ни в одной из книг.

Если система сможет:

- Найти в графе атаки, где использовалось свойство Y.
- Найти атаки на похожие на X технологии.
- Скомбинировать и предложить новую атаку (пусть даже с низкой уверенностью)

значит, архитектура работает. Если она просто ответит «я не знаю» или перескажет одну из книг — значит, не хватает замыкания цикла (планировщик + аналогии).


Новизна возникает за счёт комбинаторики в графе:

    Поиск изоморфных подграфов (тот самый ) находит структурно похожие паттерны в разных доменах. Например, паттерн «отсутствие валидации → эксплуатация» есть и в SQL-инъекциях, и в Kerberos-атаках. Система сама находит это сходство, не спрашивая LLM.

    Мутация связей: если два узла имеют похожие окружения, но не связаны, система может создать гипотетическую связь и проверить её (через поиск в книгах, через LLM, через логический вывод). Это аналог «озарения».

    Случайные блуждания с последующей проверкой: подсознание может случайно активировать два далёких узла и попросить LLM оценить, есть ли между ними связь.

Таким образом, LLM используется не для генерации ответа, а для оценки и валидации гипотез, которые граф породил сам. Это принципиально меняет динамику: система не пересказывает LLM, а выдвигает собственные идеи и просит LLM их оценить.

    Если атака требует «сетевого доступа», а цель «изолирована» — аналогично.
    Эти правила могут пополняться из книг (фреймы с условиями).

## Шаг 4: Замкнуть цикл

В subconscious_daemon (или отдельном потоке) сделать бесконечный цикл:

    Проверить очередь задач от планировщика.

    Выполнить find_analogous_attacks.

    Для каждой гипотезы вызвать validate_hypothesis.

    Записать результат в граф (с весом уверенности).

    Снова запустить планировщик, чтобы он обработал новые данные.

Этот цикл будет работать автономно, постоянно генерируя и проверяя гипотезы, пока ядро запущено. Именно это даст эмерджентность: система начнёт «думать» сама, без внешних запросов.
